# Case Study

## The challenge

The municipal license process included many connected activities performed by different roles. Applications could move forward, wait for another review, return for missing information, enter an inspection cycle or close with different outcomes.

The main challenge was to understand these variations without losing the end-to-end picture and to define the process clearly enough for software implementation.

## My role

As a Business Analyst, I analyzed the existing process step by step and independently converted the findings into a complete BPMN 2.0 model.

This work included:

- Separating the process into manageable stages
- Identifying roles and handoffs
- Mapping business decisions and their outcomes
- Showing activities that could run in parallel
- Defining correction, rejection and reinspection paths
- Checking that each scenario reached a valid process outcome
- Communicating the modeled flow to the software team

## From analysis to software

The BPMN model provided the structure needed to turn the operational process into software behavior. Activities informed workflow steps, decisions informed transition rules, and process outcomes informed application statuses.

The process was successfully implemented in the software. This made the model a working analysis artifact used during product development, not only a visual description of the business.

The full model is included in this repository because its breadth and level of detail are themselves evidence of the analysis performed. The workflow has not been reduced to a portfolio-friendly sample.

## Result

The completed work created a shared understanding of a complex process and gave the implementation team a clear view of its steps, decisions, responsibilities and exception scenarios.

The project demonstrates how detailed business analysis can connect real operational needs with an implementable software workflow.
